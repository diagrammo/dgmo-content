## Overview

A calendar draws a **span of days** as tiles. A day can hold **marks**, a number or a tag value that colours its tile, and **events**, named things on a day or across a range. It is the chart for a **daily log across weeks or a year** (commits, workouts, moods, volleys fired) and for **what happens when** (shore leave, a month of appointments). Marks show the pattern of streaks and gaps; events show the plan. The input is a plain log: one dated line per entry, and every other day stays blank.

## When to use

- **`calendar`** — your data is tied to **days**: a value per date, a tag per date, or named things on dates. The question is when, over weeks or months, the busy and quiet stretches fall, or what is planned.
- **[`heatmap`](chart-heatmap.md)** — your two dimensions are named categories (team × quarter, day-of-week × hour), not a run of consecutive dates.
- **[`line`](chart-line.md)** — the point is the exact trend and the numbers, not the shape of a habit.
- **[`timeline`](chart-timeline.md)** — the events span years or eras and the dates are the story, not a grid of days.

## Syntax

```
calendar Chart Title
year 2026
unit commit

01-02 1
01-05 8
2026-03-10 11
03-10 1
```

- **Entry line** — a date, a space, then what happens that day. A date is `YYYY-MM-DD`, `MM-DD` when the span gives a year, or a bare day number under a `YYYY-MM` month header.
- **Marks** — metadata only after the date (`alias: value, …`) is a set of marks. With exactly one group, or none, a bare number or a bare declared tag value is a mark: `01-02 8`, `01-02 Great`.
- **Events** — text after the date, then optional metadata, is an event with that name and those tags: `03-10 Dentist m: Rough`. A number on an event line is an error.
- A date written twice **adds up** for numbers. A tag mark takes the later line, with a warning. Events on one day stack.
- Entries and options may come in any order, and blank lines are ignored.

## Span

| Line                            | Span                                             |
| ------------------------------- | ------------------------------------------------ |
| `year YYYY`                     | That calendar year; `MM-DD` dates are read in it |
| `from YYYY-MM-DD`               | One year from that day (a fiscal year)           |
| `from YYYY-MM-DD to YYYY-MM-DD` | Exactly that range                               |
| Month headers only              | The months named                                 |
| None of these                   | The dates given                                  |

A date outside the span is left out, with a warning. A shorter span draws bigger tiles, so a quarter reads better than a year when the log is short.

## Layout

| Line            | Draws                                                                                                          |
| --------------- | -------------------------------------------------------------------------------------------------------------- |
| `layout weeks`  | One column per week, seven weekday rows (the GitHub shape)                                                     |
| `layout months` | One strip per month, the day of the month along it. Upright by default; `orientation-horizontal` makes rows    |
| `layout month`  | A wall calendar, a seven-column grid per month. `months-per-row N` (1 to 6) sets how many sit side by side     |

The default is `month` when any entry is an event, otherwise `weeks`. Set `layout` yourself when you want the other shape, for example `layout months` for a fiscal year.

## Number groups

A number group names what the numbers count and gives them a legend pill.

```dgmo
calendar Crew Habits, Spring Voyage
from 2027-03-01 to 2027-05-31
layout weeks
heat Knots Tied as k
  unit knot
tag Mood as m
  Great green
  Ok blue
  Seasick red
tag Duty as d
  Watch orange
  Galley teal
  Rest gray
empty Idle

03-01 k: 12, m: Ok, d: Watch
03-02 k: 8, m: Great, d: Watch
03-03 k: 20, m: Great, d: Galley
03-05 k: 5, m: Seasick, d: Rest
03-09 k: 30, m: Great, d: Galley
03-14 k: 25, m: Great, d: Watch
04-02 k: 28, m: Great, d: Galley
04-04 k: 6, m: Seasick, d: Rest
04-10 k: 35, m: Great, d: Galley
05-05 k: 33, m: Great, d: Galley
05-09 k: 7, m: Seasick, d: Rest
05-30 k: 29, m: Great, d: Galley
```

- **`heat Name [as a] [low] [high]`** — declares a number group, with indented `unit` and `max`. `as a` gives it a short alias for entries (`k: 12`).
- Five shades: zero is grey, then quartiles of the days that have a value, so one huge day does not wash out the rest. Set `max N` to pin the top shade, for example "20 or more is the darkest". Four equal bands then run up to N.
- **Implied number group** — bare numbers with no `heat` line form one number group, named by the header `unit` (and `max`), as in the Leagues Sailed example above.
- A number group never colours events.

## Tag groups

A tag group colours marks and events by value, and takes a legend pill too.

```
tag Mood as m
  Great green
  Ok blue
  Rough red
```

- Every value takes a colour, and the alias (`as m`) is what entries write: `01-02 m: Great`.
- **Bare shorthand rule** — with exactly one group (or none) a bare number or a bare declared value is a mark: `01-02 8`, `01-02 Great`. With two or more groups, every mark takes its `alias:`; a bare number then raises `E_CALENDAR_AMBIGUOUS_NUMBER`.
- A blank day reads "Not logged" in the legend. `empty <label>` renames it (`empty Idle`). The first value is not a default here, unlike in other charts.
- An undeclared value is an error, so a typo in a tag cannot go unnoticed.

## Legend and summary

The legend sits between the title and the grid, one pill per group, the first declared open. Click a pill to switch the colouring. `active-tag <Name>` opens another group first, and `active-tag none` draws no colour. A number pill reads Less … More.

The subtitle line follows the open pill: `844 commits · busiest day Mar 5`, `212 days logged · most often Great`, or `14 events`. A `subtitle` line replaces it; `no-summary` hides it.

## Ranges and events

A range is `a -> b`, and tiles every day in it. Under a month header, `29 -> 10-02` runs into the next month.

```dgmo

year 2027

orientation-horizontal
week-start monday
tag Kind as k
  Shore Leave green
  Scurvy red
  Holiday blue

03-08 -> 03-09 Scurvy watch k: Scurvy
05-31 k: Holiday

  Two weeks in **Nassau**
09-06 k: Holiday
10-11 -> 10-15 Repairs at port k: Shore Leave
12-24 -> 12-31 Winter mooring k: Shore Leave
```

Events colour their tiles with their value in the open group. A second event on a day adds a corner dot. Names and notes show on hover.

## Month blocks and notes

A `YYYY-MM` header opens a month; the entries under it take a bare day number. This is the shape for a wall calendar of a single month.

```dgmo
calendar Captain's Log, March 2027
layout month
tag Kind as k
  Battle red
  Supply blue
  Feast green

2027-03
  04 Resupply at Port Royal k: Supply
  09 -> 12 Hunt for the Black Pearl k: Battle
    Follow the **northern** trade winds
  19 Crew feast k: Feast
  26 Cannon inspection k: Battle
```

**Notes** are indented lines under an event, and show on hover. They take bold, italic and links. An indented `alias: value` line stays metadata. A note under a mark (a line with no event name) is an error.

## Options

| Option                                    | Effect                                              |
| ----------------------------------------- | --------------------------------------------------- |
| `year YYYY`, `from … [to …]`              | The span                                            |
| `layout weeks \| months \| month`         | The arrangement                                     |
| `orientation-horizontal`                  | Months as rows in `layout months`                   |
| `months-per-row N`                        | Months per row in `layout month` (1 to 6)           |
| `week-start monday`                       | Monday first. Default `sunday`                      |
| `unit <noun>`                             | What a bare number counts, singular (`unit commit`) |
| `max N`                                   | Pin the top shade of the bare numbers at N          |
| `empty <label>`                           | The legend label for blank tag days                 |
| `active-tag <Name \| none>`               | The pill open first                                 |
| `fill-tint \| fill-solid \| fill-outline` | Event bar fill in `layout month`                    |
| `no-summary`, `no-legend`, `no-notes`     | Hide that part                                      |
| `subtitle`, `footnote`, `palette`         | The chart frame                                     |

A unit that is a word takes an English plural; one with no vowel (`km`, `kg`) stays as written.

## Reading the chart

Hover or focus a day to see its value, the unit, its tags, its events and the full weekday date. Tab moves along the days.

## Appearance

| Directive | Effect |
| --------- | ------ |
| `no-title` | Hide the title line. |
| `no-legend` | Hide the legend. |

Colors come from the active palette — see [Colors](colors.md). Set the palette and light/dark theme at render time with `--palette <name>` and `--theme light|dark|transparent`.

## Common mistakes

- **`MM-DD` without a `year` line** is an error (`E_CALENDAR_SHORT_DATE_NO_YEAR`). Add `year 2026`, or write the full date.
- **A date that does not exist** (`2026-02-30`) is an error.
- **A colon or comma after a bare number** (`2026-03-10: 4`) is not a date and a value; write them separated by a space.
- **A bare number with two number groups** is ambiguous. Write `k: 12`.
- **A number on an event line** (`03-10 Dentist 4`) is an error. Events carry tags, not numbers.
- **A tag value the group does not declare** is an error. Add it under the `tag` line.
- **An event name that looks like a tag value** under the bare shorthand draws a warning; write `alias: value` to be explicit.
- **Expecting a zero line to be needed.** Days you leave out are blank, and count as zero.
- Anything that renders but looks wrong: [Troubleshooting](troubleshooting.md) is organised by symptom.
